Found and fixed during the phase
- Saved orders paid later were counted on the day they were saved → the cash would never appear in that day's drawer. Now counted on the payment day (test added).
- Margin rounding used floating point (51.25 % showed as 51.2) → integer maths.
- "Last backup" was lost after a restore → set from the file's date.

Not covered
- Delete expense / reopen day while owner mode is locked (PIN prompt): same code path as customer delete, covered in `staff.py` for other actions only.
- "Kemarin belum ditutup" banner (needs a clock change); logic is the same hooks with a different date.
- A backup with hundreds of product photos (file size / memory) on a low-end phone.
- Restore in iPad Safari (file picker + reload) — manual check.

## Security / privacy
| Concern | Assessment |
| --- | --- |
| Backup file contents | Plain JSON with customer names and phones, sales, PBKDF2 PIN hashes and recovery-code hashes. Stated on screen. Hashes are salted, 150k iterations (ADR-003), but a 4–6 digit PIN is brute-forceable offline by someone holding the file → the file must be treated as sensitive. Accepted for now (ADR-008); encryption revisited with accounts. |
| Restore as an attack path | Reachable only through Settings (owner gate). A crafted file can replace staff and PINs, but only someone already holding owner access can load it. Without an owner PIN the device is open anyway. |
| Malicious file content | Shape-validated; unknown tables dropped; nothing from the file is evaluated. Strings render through React (escaped); image fields go to `<img src>` only. Size cap 200 MB. |
| Atomicity | Clear + insert in one IndexedDB transaction; verified by test that a full round trip matches; a thrown error rolls back. |
| Expenses and closings | Any seller can record; deleting an expense and reopening a day need owner access (or the one-time owner PIN) and write audit events with the approver. Closings are immutable; "fixing" one leaves both records. On-device enforcement only (same limit as ADR-003/004). |
| Cash figures as evidence | A cashier with the device could still void/refund within their permissions before closing; the closing records what the app computed, not physical truth. The difference field is the control. |
| Exports | Expense notes go through the existing formula guard (tested: `=SUM(A1)` → `'=SUM(A1)`). |
| WhatsApp closing summary | Built locally; contains totals only, no customer data; sent only when the seller presses send. |
