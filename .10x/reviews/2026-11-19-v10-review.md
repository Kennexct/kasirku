Found and fixed
- Leaving the page during store creation left a partial menu and no store → creation is now one transaction.
- Help button's accessible name contained the topic title and collided with real actions ("Ekspor", "Tutup kasir") → neutral label "Bantuan untuk halaman ini".
- Checklist hints were cut off on phones → wrap.

Not covered
- "Mulai kosong" visual check of the empty cashier (logic covered by unit test).
- QRIS upload inside the journey (same compressor as Settings, covered in `manage.py`).
- Tablet rail with 9 items at heights below 700 px (scrolls by design).

## Security / privacy
| Concern | Assessment |
| --- | --- |
| New input | Store name (trimmed, max 60) and an optional image passed through the existing compressor (re-encoded to WebP, size-capped). Rendered as text / `<img>`. |
| First-run gate | Decided by "a store exists on this device"; cannot be used to wipe or re-seed an existing store (`createLocalStore` returns the existing one). |
| Help and checklist | Static bundled text and facts already visible to the seller; no personal data, no network. Checklist links to owner-only pages still pass the owner gate. |
| Help accuracy as a safety matter | The QRIS topic states the app cannot confirm incoming money; the backup topic states the file contains customer contacts; the PIN topic states the recovery limits. |
