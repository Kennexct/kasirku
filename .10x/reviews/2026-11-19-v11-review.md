Found and fixed
- "Kasir" translated as "Register" on receipts and role labels; "Kembali" (change) as "Back" → context hints.
- Brand wordmark was being translated ("RegisterKu") → excluded.
- "1 transactions", "1 orders" → plural-aware sentences.
- Phone bottom bar said "Other" → "More".
- The codemod's second pass wrapped code identifiers (`'cash'`, `'name'`…) → reverted; a follow-up search-and-replace also damaged one test file → restored from git. Net effect verified by type-check, 129 tests and 10 browser flows.

Not covered
- Owner-PIN screens, lockout messages and error toasts in English beyond what the flow triggers (covered by the dictionary parity test, not visually).
- PDF export in English (same strings as Excel; not opened).
- Long English labels on a 360 px phone.

## Security / privacy
| Concern | Assessment |
| --- | --- |
| New storage | One `localStorage` key with the value `id` or `en`; anything else is ignored. No personal data. |
| Translated security messages | PIN lockout, recovery-code and restore warnings keep their meaning in English (reviewed line by line: 35, 298, 464, 745, 857 and the backup warnings). |
| Injection through translations | Dictionary values are static strings; arguments are inserted as text and rendered by React (escaped) or written to CSV/Excel through the existing formula guard. `{n}` placeholders cannot reach code. |
| Language switch = reload | Cart and seller are persisted, so a reload loses nothing; an open owner unlock is dropped (in-memory by design, ADR-004) — the stricter outcome. |
